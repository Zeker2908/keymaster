# ADR-012: Bootstrap-админ

**Статус:** предложен

## Контекст

Административные эндпоинты идут через гейтвей под ролью `admin`, а правила отдаёт этот же
сервис. Нужен первый администратор, иначе создавать пользователей некому.

## Решение

- Роль `admin` создаётся миграцией. При старте, если в системе нет ни одного активного
  администратора, создаётся пользователь из `keymaster.bootstrap.admin.*` (env) с ролью
  `admin` через тот же `PrincipalService.create` (политика пароля, хэширование, аудит с
  `actor_id = NULL` и `request_id = 'bootstrap'`).
- Операция идемпотентна: при наличии активного админа ничего не делает и пароль не трогает.
- Гонка двух экземпляров: конфликт логина приводит к повторной проверке наличия админа.
  Если админа так и нет (логин занят не-админом), старт падает с понятным сообщением без
  пароля. Автоматически выдавать роль существующему пользователю нельзя: это тихая
  эскалация прав.
- Логин из конфига валидируется программно (мимо JAX-RS `@Valid` не сработает), стартовое
  выполнение ограничено таймаутом. В `%test` bootstrap выключен, включается отдельным
  `@TestProfile`.

## Последствия

- Пароль из env годится только для тестового стенда. До появления смены пароля (этап 6,
  `POST /auth/password`) использовать сервис вне стенда нельзя.
- Пароль нигде не логируется. Строку из конфига затереть нельзя: ограничение принято.
- В `%prod` значений по умолчанию нет, без них сервис не стартует (при включённом bootstrap).
- Начальные правила для гейтвея (этап 7 и nginx в стенде): публичные `POST /auth/login`,
  `POST /auth/refresh`, `POST /auth/logout`, `POST /auth/password` и разрешение
  `* /admin/**` для роли `admin`.
