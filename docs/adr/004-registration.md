# ADR-004: Регистрация только через админ-API

**Статус:** принят

## Контекст

`keymaster` это компактный IdP для закрытых систем и собственных проектов, а не публичный
сервис с самостоятельной регистрацией. Подтверждения почты и телефона нет.

## Решение

- Пользователей создаёт админ или бэкенд проекта через `POST /admin/users` под токеном
  API-клиента с узкой ролью (например, `user-provisioner`, этап 8). Самостоятельной
  регистрации нет.
- Открытую регистрацию без подтверждения почты не делаем: она привлекает мусор.
- Возможное расширение после этапа 10: инвайт-коды (админ выдаёт одноразовый код, по нему
  человек регистрируется сам).

## Последствия

- Пароль при регистрации проходит через бэкенд проекта. Для закрытых систем это приемлемо;
  более чистый вариант (одноразовая ссылка, по которой человек сам задаёт пароль) возможен
  позже.
- Роль `user-provisioner` обязана иметь явный список ролей, которые она вправе назначать
  (`projecta:user` можно, `admin` нельзя), иначе это эскалация прав. Тест на этапе 8.
- Сценарий «бэкенд сам регистрирует пользователей» заработает целиком только после этапа 8.
