# ADR-005: Хэширование паролей и политика пароля

**Статус:** принят (замер и нормализацию сверить с кодом)

## Контекст

Пароли хранятся в БД, утечка дампа не должна давать быстрый перебор. Проверка пароля это
самая дорогая операция сервиса, и она не должна блокировать event loop или исчерпывать
память при потоке запросов.

## Решение

- Argon2id (`argon2-jvm`), параметры `t=2`, `m=19456` КиБ, `p=1` (стартовые значения по
  OWASP Password Storage Cheat Sheet), подтверждены замером: около 120 мс на хэш на
  машине разработки. В БД хранится PHC-строка, `CHECK (secret_hash LIKE '$argon2id$%')`.
- Хэширование и проверка идут на отдельном ограниченном `ThreadPoolExecutor`
  (`max-concurrent-hashes`, по умолчанию 4, плюс ограниченная очередь). Переполнение даёт
  `ServiceOverloadedException` и ответ 503 с `Retry-After`. Результат возвращается на
  Vert.x-контекст запроса (`emitOn`). Массив `char[]` затирается (best effort).
- Политика пароля: длина 15–128, не равен логину (без учёта регистра), должны быть буква,
  цифра и спецсимвол из закрытого списка, пробелы запрещены. Это осознанное отступление от
  рекомендации NIST (длина и denylist вместо правил состава).
- Нормализация Unicode (NFKC) выполняется одним общим методом для политики, `hash` и
  `verify`, чтобы хэш при создании и проверка при входе видели один и тот же пароль.
- Политика применяется при установке пароля (создание, смена, сброс), но не при входе.
- Denylist частых паролей отложен. Когда понадобится: статический файл топ-N паролей в
  `HashSet` при старте, без БД и без Bloom filter.

## Последствия

- Пропускная способность входа ограничена: при 4 одновременных хэшах и 120 мс это порядка
  30 входов в секунду на экземпляр, выше сервис отвечает 503. В k6 токены нужно получать
  один раз на VU, а не на каждый запрос.
- Argon2 держит память вне кучи: около 4 × 19 МиБ. Учитывать в лимите контейнера;
  параметры перемерить в контейнере с лимитами CPU и памяти (этап 10).
- Параметры можно повышать, старые хэши остаются валидными (параметры внутри PHC-строки);
  перехэширование при входе возможно как отдельное улучшение.
