# ADR-002: TOTP как опциональный второй фактор

**Статус:** черновик (реализация после этапа 10)

## Контекст

Нужен второй фактор без SMS и почты. MFA входит в «не цели» основного плана, поэтому
добавляется только отдельным решением и отдельным этапом.

## Решение

- TOTP по RFC 6238 (приложения вроде Google Authenticator).
- Включается пользователем самостоятельно после подтверждения первым кодом, по умолчанию
  выключен, поэтому `smoke.sh` и k6 работают без изменений.
- Секрет шифруется тем же механизмом, что и приватные ключи подписи (ADR-008).
  Recovery-коды хранятся только в виде хэшей. Сброс второго фактора делает только админ.
- Логин становится двухшаговым: после пароля выдаётся одноразовый непрозрачный
  challenge-id (хранится хэшем, живёт несколько минут, это не JWT), затем проверяется код.
- Отдельный rate limit на проверку кодов: шесть цифр это всего миллион вариантов.

## Последствия

- Токены и контракт с гейтвеем не меняются, меняется только процесс логина.
- Логин на этапе 5 стоит оформлять как последовательность шагов, чтобы challenge вставился
  без переписывания.
- Библиотека TOTP выбирается на этапе реализации с проверкой актуальности.
- QR-код не нужен: сервис отдаёт `otpauth://`-ссылку, секрет можно ввести вручную.
